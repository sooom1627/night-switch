# Product

プロダクト定義（概要・基盤と仕様・Epic）。Story / Task は [GitHub Issues](https://github.com/sooom1627/night-switch/issues) を参照する。

# 1. 概要

## 1.1 プロダクト概要

本アプリは、寝るべきだと分かっているのに夜更かししてしまう人が、自分で決めた時刻に夜の行動を切り替えられるよう支えるモバイルアプリである。

介入するのは睡眠そのものではなく、夜の行動を切り替えるという意思決定である。

## 1.2 プロダクトビジョン

**完璧な人を作るのではなく、戻ってこられる人を作る。**

最終的なゴールは、アプリがなくても自分で夜を管理できるようになることである。

## 1.3 対象ユーザー

寝るべきだと分かっているのに夜更かししてしまう人（bedtime procrastination）を対象とする。

「眠くない」人は対象外とする。不眠症や概日リズムの後退（夜型）の可能性があり、就床時刻を守らせる設計と合わないためである。ストアの説明文でも明示する。

## 1.4 成功の定義

決めた時刻に行動を切り替えられたか。眠れたかどうかではない。

## 1.5 プロダクト原則

- **奪わない**: 導入の時間は就寝準備という義務ではなく、「自分の時間の後半」
- **本当の欲求に応える**: 夜更かしで埋めている欲求を、静かな形で満たす
- **閉じさせる**: 一日を「終わった」と感じられる儀式を置く
- **夜に考えさせない**: 選択肢は各段階で3つまで。推奨を最初から選択状態にしておく
- **区切りで止める**: 時刻を突きつける前に予告する
- **責めない**: 失敗という言葉、赤色、下がる数字を使わない
- **ご褒美を見える化する**: 一般論ではなく、本人自身のデータで示す
- **最小限にする**: 通知は少なく、入力は1タップで済ませ、改善は週に1つまで
- **自立へ向かう**: 介入は徐々に減らす

## 1.6 言葉の規則

命令しない、責めない、誘いかける。

| 使わない               | 使う                       |
| ---------------------- | -------------------------- |
| 寝る時間です           | そろそろ降りよう           |
| 失敗                   | 遅くなった                 |
| 〜してください         | 〜しよう／〜でも十分       |
| 連続記録が途切れました | 今日は戻る日               |
| 就寝準備               | ゆっくりする方の自分の時間 |

赤色、警告アイコン、下がるグラフは使わない。

# 2. 基盤

## 2.1 アプリケーション基盤

- React Native（Expo）で作る。ディレクトリ構造と開発の進め方は stamp-log と同じにする
- iOS を先行する
- iOS のビルドは EAS Build で行う
- 最初のリリースは Screen Time を使わず、朝の判定は本人の自己申告（1タップ）にする。Screen Time による自動判定は E-003 で後から足す
- HealthKit は使わない

## 2.2 確度の表記

設計の根拠には確度を付ける。〔根拠あり〕〔一部根拠あり〕〔仮説〕のいずれか。文献は原典を確認してから引用する。未確認の文献には〔未確認〕と書く。

## 2.3 最初の質問（オンボーディング）

質問は「望む結果 → 障害 → プラン」の順に並べる（MCII、Oettingen ら〔未確認〕）。答えは夜の通知や画面の文言としてそのまま使う。使わない質問は置かない。

1. 何時に起きたい？（時刻）
2. ちゃんと寝られたら、本当は何がしたい？（望む結果）: 朝に自分の時間がほしい（運動・勉強・読書）／日中に集中したい／体調を整えたい／気分を安定させたい／その他。朝の時間を選んだ人は、内容を一言で書く（例: 朝ラン）
3. 夜、何に捕まりやすい？（障害）: 仕事／動画／SNS／ゲーム（複数選択）。そのうち一番やめにくいものを1つ選ぶ
4. その時間で、本当は何を満たしたい？（欲求）: 自分だけの時間／頭を空っぽにしたい／誰かとつながっていたい／何かを進めた感じがほしい／楽しさや刺激がほしい
5. ルールを3案から1つ選ぶ（プラン）: 一番やめにくいものを中心に、種類の違う3案を出し、推奨を選択状態にする
6. 導入メニューを段階ごとに3つずつ選ぶ。Q4 の欲求に合わせて推奨を出す
7. 導入をいつ始める？: 就寝の45分・60分・90分前（初期値60分前）。切り替え時刻は起床時刻から逆算した値を提案する（成人の推奨睡眠時間は7時間以上、AASM/SRS 2015〔未確認〕）
8. 「続き」をいつ思い出させる？: 通勤中・昼休み・帰宅後（E-006 で使う）

答えは後から変えられる。

## 2.4 ルール

ルールは、決めた時刻に何をするかを1文で表したものである。

| 種類                 | 例（動画の場合）                                  |
| -------------------- | ------------------------------------------------- |
| 環境を変える（推奨） | 23:00になったら、スマホを充電場所に置く           |
| 始めることを止める   | 22:45以降は、新しい動画を再生しない               |
| 場所を移す           | 23:00になったら、動画アプリを閉じて寝室へ移動する |

動画・SNS・ゲームはスマホという共通の原因でまとめる。仕事だけは「次にやることを1行メモしてPCを閉じる」を中心にする。

## 2.5 導入

導入は「降りる → 落ち着く」の2段階で、メニューはその場で選ぶ。興奮した状態から静かな行動へいきなりは移れない（Nicassio et al. 1985〔未確認〕）。段階的に下げると移行しやすいという点は〔仮説〕。

- 長さは45分・60分・90分（初期値60分、各段階は半分ずつ）。最適な長さの確立したエビデンスはない
- 各段階のメニューは3つまで。オンボーディングで本人が選んだものから出す
- 音声メディアは、スマホを手元に置かない・連続再生しないことを条件にする

| 段階     | メニュー例                                       |
| -------- | ------------------------------------------------ |
| 降りる   | 明日の準備、片付け、シャワー、入浴、音楽・ラジオ |
| 落ち着く | 紙の本、瞑想・呼吸法、ストレッチ、明日のメモ     |

欲求に合わせた推奨〔仮説〕:

| 満たしたいもの     | 降りる                               | 落ち着く       |
| ------------------ | ------------------------------------ | -------------- |
| 自分だけの時間     | 好きな音楽、シャワー                 | 紙の本         |
| 頭を空っぽにしたい | 入浴、片付け                         | 瞑想、呼吸法   |
| 誰かとつながりたい | 「おやすみ」を送ってからスマホを置く | 本、ストレッチ |
| 進めた感じがほしい | 明日の準備、続きは明日               | 明日のメモ     |
| 楽しさや刺激       | ラジオ、音楽                         | 物語の本       |

## 2.6 夜の瞬間

| 瞬間            | タイミング         | 内容・文言                                                                                                                     |
| --------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| A. 予告         | 導入の10分前       | 「次の1本は始めずにいこう」                                                                                                    |
| B. 切り替え     | 導入開始時         | 「ここからは、ゆっくりする方の自分の時間」＋明日本当にしたいこと（例: 「明日は 6:30 から朝ラン」）。降りる段階のメニューを選ぶ |
| C. 落ち着く     | 降りる段階の終わり | 落ち着く段階のメニューを選ぶ通知。本人がオフにできる                                                                           |
| D. 閉じる儀式   | 導入の最後         | 「今日よかったことを1つだけ」（1タップか一言）〔仮説〕                                                                         |
| E. 崩れている夜 | 0時ごろに1回だけ   | 「今からでも、降りれば十分。」記録の扱いは変えない                                                                             |

通知には、オンボーディングで本人が選んだ言葉（ルール・動機）をそのまま入れる。

## 2.7 朝の判定

- 朝に1タップで「切り替えた／遅くなった」を記録し、同じ画面で「今朝の調子は？」を1〜5で答える
- 判定は2択。少しの遅れは初回設定の許容幅（例: ±15分）に吸収する
- 最初のリリースは自己申告。E-003 以降は Screen Time の判定を使い、障害が「仕事」の人は自己申告のまま

## 2.8 Miss 翌日と Back on track

- 遅くなった翌日の表示は「昨日は遅くなったね。今日は戻る日」。ルールは変えず、Q2 の動機を表示する
- 戻れたら「Back on track」と表示し、明日本当にしたいことに結びつける
- 2日続けて遅くなっても責めない。表示は「今日も戻る日」のまま

## 2.9 Flex Night

- 前日までに宣言した場合のみ、週1回まで
- 遅くなった後から Flex 扱いにはできない。計画した例外と遅くなった夜を区別するため

## 2.10 週次

- 振り返りは1行: 「Miss ○回／すべて翌日に戻れた ✓」。Miss 回数と戻れた数は必ずセットで出す（戻れた数だけだと、Miss が多いほど見栄えが良くなるため）
- 改善案は週に1つだけ: 導入の長さ、メニューの入れ替え、ルールの変更のいずれか
- 質問は最大1問（例: 「このルールは合っていた？」「布団に入ったとき眠かった？」）
- メニューの入れ替え: よく選ばれ、選ばれた夜に切り替えられたことが多いメニューを残し、数週間選ばれないものは別の候補と入れ替える。相関であり因果ではない

## 2.11 続きは明日

- 切り替えの通知に［続きは明日］を置く。仕事は次にやることを1行メモし、動画や SNS は共有メニューからリンクを預ける
- 翌日、Q8 で選んだ時刻に1回だけ思い出させる。預けたものがある日だけ通知する
- 目的はやめるときの心理的なコストを下げること。中身を消化させることではない。本格的なリンク管理にはしない

## 2.12 介入の漸減

1週目は手厚く、2週目は効いたルールに絞り、3週目は質問を減らし、4週目以降はキューだけを残す。

## 2.13 やらないこと

| 機能                              | 理由                                       |
| --------------------------------- | ------------------------------------------ |
| +30分延長                         | 先延ばしを正式に認めることになる           |
| Minimum Mode                      | 基準が2つになり、夜の判断が増える          |
| 毎晩の障害入力                    | 負担が大きい。初回設定の1回にまとめた      |
| 3段階判定                         | 許容幅に吸収し、2択にした                  |
| 「起床まで6h45m」などのコスト表示 | 現在バイアスのため、夜の自分には響きにくい |
| HealthKit の入眠データ            | 使わない（2026-10-08 決定）                |
